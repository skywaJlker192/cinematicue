# RISK_REGISTER.md — Реестр рисков Cinematheque

## Риски безопасности

| Риск | Причина | Вероятность | Влияние | Мера снижения |
|------|---------|-------------|---------|---------------|
| Утечка `.env` с `JWT_SECRET` | Файл случайно попал в Git | Средняя | 🔴 Высокое | `.gitignore`, `.env.example`, проверка `git status` перед коммитом |
| Доступ к чужим заказам | Нет проверки `user_id` в API | Средняя | 🔴 Высокое | Проверять `req.user.id === order.user_id` перед выдачей данных |
| Уязвимая зависимость | Старая версия `express`/`bcrypt` | Средняя | 🟡 Среднее | `npm audit`, регулярное обновление зависимостей |
| XSS через ввод данных | Неэкранированный ввод в форме | Низкая | 🟡 Среднее | Санитизация ввода на фронтенде и бэкенде |
| Bruteforce на `/api/login` | Нет rate limiting | Средняя | 🟡 Среднее | Добавить `express-rate-limit` на эндпоинты авторизации |

## Риски эксплуатации

| Риск | Причина | Вероятность | Влияние | Мера снижения |
|------|---------|-------------|---------|---------------|
| Потеря данных (`db.json`) | Нет автоматического бэкапа | Средняя | 🔴 Высокое | `backup.bat`, ручное копирование, в будущем — PostgreSQL |
| Сервис "засыпает" на Render | Бесплатный тариф без ping | Высокая | 🟡 Среднее | Использовать UptimeRobot для пинга каждые 5 минут |
| Нет мониторинга ошибок | Не настроены алерты при 500 | Средняя | 🟡 Среднее | Добавить логирование ошибок и healthcheck |
| CORS разрешает все в dev | `app.use(cors())` без ограничений | Низкая | 🟡 Среднее | Настроить `CORS_ORIGIN` в production |
| Нет HTTPS валидации в dev | Нет проверки сертификатов локально | Низкая | 🟢 Низкое | В production использовать HTTPS, настроить HSTS |

## Матрица приоритетов

### 🔴 Критические (исправить в первую очередь):
1. Проверка доступа к чужим заказам — добавить валидацию `user_id`
2. Бэкап данных — настроить автоматическое копирование `db.json`

### 🟡 Средние (запланировать):
1. Rate limiting на `/api/login`
2. Санитизация ввода для защиты от XSS
3. Мониторинг ошибок и алерты

### 🟢 Низкие (улучшения):
1. Регулярное обновление зависимостей
2. Документирование security-политик

## Вывод
Проект не содержит критических уязвимостей, блокирующих эксплуатацию. Основные риски связаны с отсутствием автоматического бэкапа и проверкой прав доступа. Рекомендуется исправить критические риски в течение 1 недели перед демонстрацией.
